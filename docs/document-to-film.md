# 从一篇文档到一条片子（document → film）

这份说明写的是**人（或 agent）该怎么走这一步**，不是引擎内部流程。引擎负责「文案 → 成片」，
而「44,484 字的报告 → 1,066 字的解说稿」是编辑判断，没有任何脚本能替你做完。
实测案例：`TOC瓶颈理论从入门到精通.md`（3,522 行 / 44,484 字）→ 55 场 / 318s 竖屏片。

## 1. 先量出预算，再动笔

用实测语速换算时长（ListenHub「解说小明」中文实测）：

| 语速 | 1066 字 → | 结论 |
|---|---|---|
| 3.35 字/秒（约 201 字/分钟） | 318s = 5:18 | **字数 ÷ 3.35 ≈ 片长（秒）** |

所以「5 分钟的片子」= **约 1,050 字解说稿**。一篇 4.4 万字的报告压到这个长度，是 **42:1**
的压缩比——这不是「朗读全文」，是**重写一篇能听的稿子**。先把这个数字摆出来，再决定
要不要做 3 分钟版（≈600 字）还是 8 分钟版（≈1,700 字）。

## 2. 读结构，不读全文

```bash
grep -n '^#\{1,4\} ' doc.md | head -80     # 先看骨架
```

然后只精读**承载论点的那几段**：结论区、方法区（步骤/流程）、反常识区（为什么难）、
判断区（作者的最后结论）。案例里真正进稿的是 5 个结论段、五步聚焦法、五个「为什么学不会」、
最终判断——其余（横向比较的 12 个对象、历史细节）只贡献一两句。

## 3. 定「脊柱」，一句话一个 beat

一份能看的片子要有一条脊柱，不是目录。案例的六幕：

| 幕 | 内容 | 稿子里的句子 |
|---|---|---|
| 1 | 反直觉的开场事实 | 降本增效了，订单还是延期 |
| 2 | 概念翻转 | 传统管理问效率，TOC 问约束；企业是一条链 |
| 3 | 方法 | 五步聚焦法（识别/挖掘/服从/提升/防惯性） |
| 4 | 难点 | 认知瓶颈；优势与弱点同源；学不会的五个原因 |
| 5 | 来历 | 排程软件 →《目标》→ 思维流程/关键链/战略战术图 |
| 6 | 判断 | AI 解决信息获取，TOC 解决因果关系；最终一句 |

写稿规则（都是被引擎的切场逻辑逼出来的）：

- **一句一行**（`copy.txt` 每行一句），句末用全角标点——TTS 的语速和停顿靠标点，缺标点的稿子会念得又平又快。
- **每句一个完整语义单元**，别写「因为……所以……」的长复合句：超过 8.2s（≈28 字）引擎会在内部标点处切场，切出来的半句会变成独立的画面。
- **短句优先**。案例 32 句里 26 句在 26 字以内。
- 数字写中文（「百分之八十」）比写 `80%` 念得稳；`TOC`/`AI`/`OKR` 这类缩写会逐字母念，可以留，但见下一条坑。

## 4. 生成旁白：**分段生成 + 每段体检**

**这一步有坑，而且不看波形发现不了**：ListenHub TTS 会静默丢句。实测两次整篇生成各出现一段
41.3s / 58.5s 的纯静音（对应文本只有约 6–7s），ASR 的 token 时间戳会直接跨过那段静音。
后果是管线里出现 `scenes[N].durationSec must be > 0` 或整片时间轴错位。

固定动作：

```bash
# ① 按幕切段（每段 ≤ ~450 字），逐段生成 TTS
# ② 每段体检
python3 scripts/check_narration.py audio/chunk-*.mp3      # 有 >3s 静音就重生成那一段
# ③ 拼起来（段间插 0.45s 静音），整条再体检一次
python3 scripts/check_narration.py audio/narration.m4a
```

丢了就**重生成那一段**（不是重生成整篇——省钱，也少一次踩坑机会）。案例里两次丢句都发生在
「TOC」+短句+「：」附近，重生成时把 `TOC 说：` 改成 `它说，`、并把 390 字的段拆成两段之后就干净了。
`make_video.py` 现在也会在 `--narration` 上自动做一次静音检查并告警。

## 5. 进管线

```bash
# ① 词级时间轴（不是手写 beat）
coli asr -j audio/narration.m4a > audio/narration-asr.json
python3 scripts/align_transcript.py --transcript audio/narration-asr.json \
    --text script/copy.txt --out audio/narration-aligned.json
#    相似度 < 0.85 就回头看第 4 步（八成又丢句了）

# ② 风格推荐 → 组装 → 渲染 → 字幕 → 终合成 → verify
python3 scripts/make_video.py --copy script/copy.txt --project proj \
    --style hand-sketch --go \
    --narration audio/narration.m4a --transcript audio/narration-aligned.json \
    --bgm audio/bgm.wav --speaker-hint "解说小明"
```

BGM 要**先按片长裁好**（`ffmpeg -stream_loop N -i bgm.wav -t <片长> -af afade…`），
finalize 只负责按 0.18 音量混进去，不会替你循环。

## 6. 这一轮还顺手验证了什么

- 55 场、318s、5 套版面（数字主角/一句话大片/对照/步骤/论证）按句子形状逐场分配，最长同版面连续 2 场。
- 「第 N 步」句自动拿到进度版面（进度条 + 巨号步序 + 步骤名），N 与总步数都从文案推。
- 素材：hand-sketch 现在也走自动检索（`MATERIAL_PLANS`），取不到图就整块消失、
  留下手绘的空图框 + 图注（`data-hide-when-empty`）。
- `derive_timing.py` 的取整修正：场景时长按「取整后的边界相减」，否则 0.01s 的舍入漂移会让
  校验器报 `overlaps the previous scene`（案例里正好在第 38 场触发）。
